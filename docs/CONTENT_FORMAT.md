# Content format v1

「ランダム 1」はこの形式の実例です。本文・読み・解説を1つの記事JSONで管理し、音声ファイルだけを別に保存します。既存の文字列形式を保ったまま、日英の説明と出典リンクを追加しました。

正式な実行時スキーマは [`src/lib/schema.ts`](../src/lib/schema.ts) の `contentSchema` です。`Content`, `Translation`, `CatalogEntry` のTypeScript型はZodから推論します。公開・非公開で形式は同一です。

## 配置

Libraryの制作候補は `src/data/library-plans.ts` に保存し、`/ja/library/plans/`・`/en/library/plans/` に表示します。公開済み記事のJSONとは別で、本文・音声は生成しません。`group: passages` は候補箇所が挙がっている作品、`group: scope` は抜粋範囲をさらに検討する作品です。この区分は内部の調査メモとして保持し、画面では見出しを分けず一つの一覧にします。公開時期や制作順はこの区分では指定しません。

同じ `id` の公開用Library記事が `ready` になった候補は「今後扱いたい題材」の表示から外れ、Library一覧で読めるようになります。候補データの順序・資料メモは保持します。非公開記事や `draft` / `review` の作成だけでは候補を非表示にしません。

制作候補の表記は以下に統一します。

- `title`：日本語は『邦題』、英語は英語名。著者名や章名を混在させません。
- `metadata`：著者・言語・年代の順に、中黒（` · `）で区切ります。未記載の情報を推測で補いません。
- `passage`：候補箇所だけを簡潔に記し、末尾の句点や「抜粋範囲を検討」の繰り返しは付けません。章・巻などの番号は算用数字を使い、引用した固有の章名は保持します。
- `description`：内容を簡潔な名詞句で記します。
- `note`：原語の表示・音声など、読者向けの補足だけを記します。
- `url`, `sourceNote`：資料リンクと版に関する調査メモ。内部データにだけ保持し、ページには表示しません。

表示項目には日英両方を記入し、候補箇所・内容・補足のラベルはUI辞書側で付けます。

公開：`content/public/<type>/<id>/content.json`。非公開：外部ルートの `content/<type>/<id>/content.json`。`type` とディレクトリ名、`id` とディレクトリ名を一致させます。

`id`, `slug`, unitの `id` は英小文字・数字をハイフンで区切った形式です。`id` と `slug` は全教材を通じてそれぞれ一意にします。表示URLは `ja/read/<slug>/` または `en/read/<slug>/`、音声参照には `id` を使います。

Grammarも既存の意味単位・9言語エントリー形式を使います。Practicalの会話では各発言を1つの意味単位とし、短い質問・応答と、単独で使える表現を組み合わせます。記事全体を一続きの会話にはせず、異なる場面を小見出しで区切ります。音声未生成の記事は `audio` を省略し、本文・必須の読みだけで公開できます。追加した7記事は本文・読みと話者の性などの補足を先行して収録し、現在、全公開教材とともに語彙・文法の詳しい日英解説を整備しています。編集基準と進捗は [EXPLANATION_PLAN.md](EXPLANATION_PLAN.md) を参照してください。

## 教材メタデータ

| フィールド | 内容 |
|---|---|
| `schemaVersion` | 必須、現在は整数 `1` |
| `id`, `slug` | 保存・URL用の識別子 |
| `type` | `practical` / `grammar` / `library` |
| `title`, `description` | 教材タイトルと説明。文字列または日英オブジェクト（空欄不可） |
| `originalLanguage` | 原文の言語コード |
| `author` | 原文の著者 |
| `bibliography` | Library一覧用の書誌情報。`originalTitle`, `originalAuthor`（原語の文字列）、`title`, `author`（日英の表記）。既存データとの互換性のため省略可 |
| `sourceTitle`, `sourceURL` | 原典名とHTTP(S)出典URL。URLなしは `""` |
| `rights`, `license`, `attribution` | 原文の権利説明、ライセンス、帰属情報 |
| `editorialNote` | 任意の制作方針・校閲状況の説明。文字列または日英オブジェクト |
| `excerpt` | 任意。`isExcerpt`（真偽値）、`location`（章・段落・範囲。文字列または日英オブジェクト）。Library一覧の説明と記事の出典情報で共有 |
| `tags` | 表示用の文字列配列 |
| `difficulty` | 任意の難易度表示 |
| `publicationStatus` | `draft` / `review` / `ready` |
| `createdAt`, `updatedAt` | 有効な日付 `YYYY-MM-DD`。更新日は作成日以降 |
| `units` | 意味単位の配列。少なくとも1つ |

未知のトップレベルフィールドは拒否するため、形式の変更にはスキーマ更新が必要です。privateというフィールドはありません。**配置場所が公開・非公開を決めます。** privateのreadyをpublicへ自動昇格させることはありません。

## 対応する定型表現を載せない場合

同じ使い方の自然な定型表現がない場合や、一対一の訳を載せると誤解を招く場合は、その言語を `languages` に無理に追加しません。unitの任意フィールド `noEquivalent` に、言語コードをキーとして日英の理由を記入します。例：`"noEquivalent": { "en": { "ja": "この場面の定型句は載せません。", "en": "No set phrase for this situation is listed." } }`。既存の本文形式は変わりません。

- 各言語は本文と理由のどちらか一方だけを持てます。未知の言語コード、空の理由、両方の指定は拒否します。
- readyでは標準9言語それぞれに本文または理由が必要です。単なる未記入は引き続きエラーです。すべての言語を理由だけにして本文をなくすこともできません。
- 理由は日英UIで表示する説明です。`text`、`ttsText`、読み表記、音声参照を作りません。TTSは言語を明示指定した場合も、そのunitをスキップします。
- 画面では言語名と理由を表示し、「準備中」と区別します。文化・地域・話者を問わず表現が存在しないという断定には使わず、どの使用場面の対応を見送ったかを説明します。

## 日本語・英語の解説

全教材の解説拡充を再開する場合は [EXPLANATION_HANDOFF.md](EXPLANATION_HANDOFF.md) の高速生成手順に従います。直近の追加分と同程度の分量を維持し、既存の確認済み解説は保持してください。本書は保存形式の参照用であり、各バッチでの全文再読・資料調査・表示確認を要求するものではありません。必要な節だけを参照します。

`title`, `description`, `rights`, `attribution`, `editorialNote`、語彙の `meaning`、文法の `point` / `explanation`、`notes` の各項目には、従来の文字列と次の日英オブジェクトのどちらも使えます。

```json
{ "ja": "少し早く。", "en": "A little early." }
```

オブジェクトを使う場合は日英両方が必須です。`text` と `ttsText` は学習対象の言語の文字列のままにします。`term` は原語の見出しです。日本語版・英語版のために記事やMP3を複製しません。UI表示時に `src/lib/localized.ts` が該当する説明を選び、自動翻訳は行いません。

## 意味単位と言語エントリー

unitの任意フィールド `heading` は、その意味単位から始まる場面の小見出しです。日英オブジェクト（推奨）または従来形式の文字列を受け付けます。省略した既存記事の表示は変わりません。本文・音声に見出しを混ぜず、表示順を変えるときも既存unit IDは維持します。

```json
{
  "id": "u001",
  "languages": {
    "ja": {
      "text": "山路を登る。",
      "ttsText": "やまみちをのぼる。",
      "vocabulary": [{ "term": "山路", "meaning": "山の中を通る道" }],
      "grammar": [{ "point": "〜を", "explanation": "移動する経路を示します。" }],
      "notes": ["読みを確認してから音声を生成してください。"],
      "translation": { "method": "original", "reviewStatus": "unreviewed", "attribution": "制作者名" },
      "audio": { "path": "library/my-first-work/u001/ja.mp3", "origin": "chatterbox", "qualityStatus": "unreviewed" }
    }
  }
}
```

これは現在の形式におけるunit部分の例です。記事の自動追加は行いません。

- `text`：画面に表示する正式な本文。HTMLとして解釈しません。
- `ttsText`：音声用に調整した読み。readyでは標準9言語に必須。追加原語には不要。
- `pronunciation`：解説冒頭に表示する読み。readyではアラビア語・中国語に必須（下記参照）。
- `vocabulary`：`term` と `meaning` の配列。
- `grammar`：`point` と `explanation` の配列。
- `notes`：文化・文学・表現に関する説明の配列。
- `references`：任意。解説で参考にした資料の `{ "title": "資料名", "url": "https://…" }` 配列。HTTP(S)のみ。
- `translation.method`：`original` / `human` / `ai-assisted` / `provided`。`provided` は提供文の転載で、翻訳者・生成方法を推測しない場合に使います。
- `translation.reviewStatus`：`unreviewed` / `reviewed`。
- `translation.attribution`：訳・原文の制作者、補助ツール、校閲者等の記録。
- `audio`：任意。未生成の場合は省略でき、参照だけ先に書いても問題ありません。
- `audio.origin`：`chatterbox` または手動収録の `human`。
- `audio.qualityStatus`：`unreviewed` / `reviewed`。生成直後は未確認。

`vocabulary`, `grammar`, `notes` は空配列でも保存できます。不要な説明を無理に埋める必要はありません。各意味単位が異なる数の文から成っていても構いません。対応関係は文番号ではなくunit IDで維持します。

## アラビア語・中国語の読み表記

記事のアラビア語と中国語は、解説を開いた直後、単語・語法・文法の前に読みを表示します。各言語エントリーに `pronunciation` を保存します。readyでは両言語に必須です。draft / reviewでは未記入のまま作業できます。

```json
{
  "pronunciation": {
    "system": "pinyin",
    "text": "Hǎojiǔ bù jiàn! Nǐ zuìjìn zěnmeyàng?",
    "note": {
      "ja": "発音時には hǎojiǔ → háojiǔ、bù jiàn → bú jiàn と変化します。",
      "en": "In speech, hǎojiǔ becomes háojiǔ and bù jiàn becomes bú jiàn."
    }
  }
}
```

- `system`：アラビア語は `arabic-romanization`、中国語は `pinyin`。
- `text`：表示専用の読み。日英UIで共有し、左から右に表示します。
- `note`：その文に特有の補足だけを記します。日英オブジェクトまたは従来の文字列形式。その文に現れる変調、話者・相手の性、休止形などが対象です。該当する補足がなければ省略します。表記方式の一般論・記号の凡例・本調で表す方針・軽声に声調記号を付けない説明は、各文の読みの下に繰り返し掲載しません。

中国語の画面見出しは日本語版で「拼音」、英語版で「Pinyin」とします。読者向けの共通ルール・記号の凡例・参考資料は、ホームから開ける `/ja/guide/`・`/en/guide/` にまとめます。読み表記の一般的な参考資料は各文の `references` に繰り返し登録しません。その文の文法などに固有の参考資料は残せます。以下の一般的な表記規約は執筆者向けです。

読みは著者が文脈を見て作成し、本文とセットで確認します。自動生成や機械検証だけで正しい発音を保証するものではありません。検証は必須項目・言語と方式の一致・文字種を確認し、音節ごとの読みや声調の正誤までは判定しません。数字付き拼音（ni3など）は使用できません。既存のready記事に読みがない場合は補ってからビルドしてください。

### アラビア語：学習用ラテン文字転写

現代標準アラビア語（MSA）を基本にします。IPAを知らなくても読みやすく、カタカナでは失われやすい音の区別を残すためのサイト内の方式です。[米国議会図書館の転写表](https://www.loc.gov/catdir/cpso/romanization/arabic.pdf)の文字対応を参考にしますが、ALA-LC準拠を名乗るものではありません。

- 短母音 a / i / u、長母音 ā / ī / ū、二重母音 ay / aw。
- ح = ḥ、ص = ṣ、ض = ḍ、ط = ṭ、ظ = ẓ、ع = ʿ、ء = ʾ。
- ش = sh、خ = kh、ث = th、ذ = dh、غ = gh。その他は一般的な b / t / j / d / r / z / s / f / q / k / l / m / n / h / w / y。
- 重子音は文字を重ねます（例 ladayya、muʾakhkharan）。ʿとʾは普通のアポストロフィと区別します。
- 単語ごとの読みを基本に、文中の格語尾も示します。冠詞の太陽文字への同化は aṣ-ṣabāḥa のように示します。語をまたぐ母音脱落や文末の休止形は本文の読み行には反映せず、必要な違いを `note` に記します。
- 母音のないアラビア文字からは一意に読めない場合があります。ḥāluka / ḥāluki のような性による違いは、採用した読みと別形を補足します。

冠詞の連音と同化については [Madinah Arabic](https://madinaharabic.com/free-content/grammar/lesson-3/part-7) を参照しています。音声から書き起こすのではなく、本文に対する学習用の読みなので、生成音声の実際の読みと一致する保証はありません。

### 中国語：声調記号付き漢語拼音

普通話を基準とし、声調は mā / má / mǎ / mà のように母音に付けます。軽声は記号なし、üはそのまま記載します。語のまとまりで分かち書きし、声調は原則として本調（辞書形）で表します。第3声の連続や「一」「不」の変調は、読み行を書き換えず `note` で説明します。この区別は [MITの声調教材](https://web.mit.edu/jinzhang/www/pinyin/tones/) を参照しています。

`pronunciation` は `text`（本文）や `ttsText`（音声入力）とは別です。読みの追記・修正だけでMP3を再生成する必要はありません。音声生成には、引き続き中国語・アラビア語の元の `ttsText` を渡します。

## 言語の順序

`ja, en, es, fr, de, ru, ar, zh, ko`。JSONオブジェクトのキー順序には依存しません。UI・検証・Pythonは `config/languages.json` を参照します。全言語再生では「u001の9言語 → u002の9言語…」の順です。

各意味単位の9言語は、日本語版では定義順、英語版では英語→日本語→残り7言語の順で表示・連続再生します。各文に1つの折り畳みがあり、開くと単語・語法・文法・表現の解説と参考資料が表示されます。アラビア語本文と語彙には `lang="ar" dir="rtl"` を付け、日本語のUI全体はLTRのままにします。

Libraryの原語が標準9言語に含まれない場合、`config/original-languages.json` の `grc`（古代ギリシア語）、`la`（ラテン語）、`sa`（サンスクリット）、`it`（イタリア語）を `originalLanguage` に指定できます。各unitの `languages` に同じコードで原文を追加し、`translation.method` は `original` にします。readyでは標準9言語に加えてその原文が必須です。別の追加原語の混在は許可しません。

追加原語は表示専用で、`audio` は指定できません。日本語版では日本語の直後、英語版では英語の直後に挿入します。標準9言語の設定・音声生成対象は増やしません。

Practical・Grammar・Library共通で、実際に利用可能な音声があるエントリにのみ、スピーカーの線画アイコンと「音声あり」を添えます。音声のないエントリにはラベルを表示しません。Libraryは音声の有無で分けず一つの一覧で表示します。音声が一つもない記事では再生操作を表示せず、本文・解説・出典を読めます。

## draft / review / ready

- draft / review：一部言語のみ、またはunitの `languages: {}` でも保存可能。localだけに表示。
- ready：すべてのunitで標準9言語を本文または `noEquivalent` の理由でカバーします。本文には `text` と `ttsText`、アラビア語・中国語には `pronunciation` が必要。音声の実在や翻訳校閲済みは必須ではありません。
- publicationStatusと校閲・音声品質は独立です。readyでも校閲前の内容はunreviewedとして扱います。

誤った日本語 `ttsText`、不正なID・URL・音声パス、重複unitはdraftでもエラーです。公的な権利確認はスキーマだけでは保証できません。

## 日本語の読み

日本語はひらがな・句読点・空白・長音符を許可します。漢字、カタカナ、英字、数字を検出するとエラーです。数字も「にせんにじゅうろくねん」などの読みに直します。表示文の正しい文字表記は `text` に残します。

`hiragana.py` は任意の補助で、出力候補を人が確認して転記します。人名・地名・多音字、助詞の扱いなどを確認してください。保存された手編集の `ttsText` が正です。CLIは日本語で `text` にフォールバックしません。

## 音声ファイル

参照は `type/id/unit/lang.mp3` に限定します。public/privateのプレフィックスとGitHub Pagesのbase pathはビルド側が付与します。絶対パス、外部URL、`..`、別教材への参照、symlinkは許可しません。

Chatterboxで生成したMP3の隣には `.mp3.json` が必要です。ビルド時に生成元、入力・言語、MP3ハッシュを確認します。手動で音声を変更した場合は再生成するか、正当な手動収録として `origin: "human"` に変更します。mockは収録しません。音声の権利・品質は公開前に確認してください。

本文を編集したら、必要に応じて `updatedAt` を更新し、校閲・音声品質の状態を戻します。TTS入力を変更した場合は生成CLIが変更を検出します。ID/unit IDを変更するとパスも変わるため、既存コンテンツの識別子はなるべく維持してください。

## 連続再生と保存容量

「ランダム 1」の配置は次のとおりです。

```text
content/public/practical/random-1/content.json   # 90組・810言語エントリー・読み・日英解説・音声参照
media/public/practical/random-1/
├── u001/{ja,en,es,fr,de,ru,ar,zh,ko}.mp3
└── u002/{ja,en,es,fr,de,ru,ar,zh,ko}.mp3
```

各MP3の隣に `.mp3.json` の生成記録がありますが、これは配信しません。現在の音声は90組 × 9言語の810ファイル。結合版を持たず、ブラウザの1つのaudio要素にキューの次のファイルを渡します。個別再生は1件、意味単位のボタンはその9言語、記事先頭のボタンは全意味単位を順番に再生します。未生成の音声はスキップし、件数を表示します。別の再生ボタンを押すと前のキューを置き換え、停止すると文間の待機も取り消します。

この方式なら1文の差し替えで済み、個別・9言語・記事全体のために音声を三重保存する必要がありません。速度と文間の間隔はブラウザで変更できます。ただしファイル切替には読み込み時間があり、間隔を0秒にしても完全に継ぎ目のない再生は保証しません。将来、オフライン再生用に1ファイルが必要になったときだけ、配布用の結合版を書き出せます。

本文・解説だけを変更した場合、`ttsText` に変更がなければ音声を再生成する必要はありません。読みを変えたときは次を実行します。

```bash
npm run tts -- --scope public --work random-1
npm run validate:content
npm run build:public
```

CLIは変更された入力だけを再生成します。語彙・文法の説明だけを編集する場合も、日英両方を更新してください。文章の意味や読みを変えたら校閲状態を見直し、`updatedAt` を更新します。
